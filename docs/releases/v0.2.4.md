# RootWalk v0.2.4

RootWalk v0.2.4 makes dynamic-frontier replacement transactional and adds a
source-backed, recommendation-only path for peer-isolated queue congestion.
OpenRCA remains an Adapter and evaluation suite; Harness Core contains no benchmark
row, component, answer, label, or evaluator-tolerance branches.

## Transactional dynamic frontier

- Context now exposes a binding `leader_upgrade_contract` whenever another subject
  has strictly stronger direct typed mechanism Evidence than the current best.
- A replacement must atomically create or select the challenger Hypothesis, submit a
  same-subject `supports` assessment, and explicitly replace current best. Rejected
  Decisions persist none of those fields, so retries must resubmit the complete state
  transition.
- Runtime independently validates the same lexicographic mechanism rank and score.
  It still does not manufacture a Hypothesis, infer Evidence polarity from status or
  prose, or silently rewrite the model's subject, statement, references, or leader.
- Current-best support must come from the Hypothesis subject. Topology-neighbor
  Evidence may motivate a check, but cannot directly select the leader.
- A newly discovered eligible profile requires structured Hypothesis creation when no
  live candidate exists. Decision summaries are never treated as committed state.

## Evidence and closeout behavior

- The Telecom Adapter recognizes a peer-isolated, direction-aligned queue-congestion
  event from multiple strong queue signals. It is a low-rank material event eligible
  only for a Recommendation; it cannot produce a formal Finding by itself.
- Low-rank queue events do not stop challenger discovery. Higher-rank trace errors,
  state transitions, and fault-ready mechanisms remain discoverable and replace a
  weaker leader when their direct Evidence is stronger.
- Occurrence-only output accepts a single profile only when it is fault-type-ready.
  A generic material event cannot turn an ambiguous onset into a claimed root-cause
  time.
- Repeated provider schema failures at physical closeout become an auditable Runtime
  Abstention. Before closeout, the model receives a fresh context and may retry.
- Finding still requires complete material-anomaly explanation. Recommendations retain
  unresolved anomaly IDs, and Market unseen still exports no answer.

## Frozen evaluation

The release candidate is `m113 / openrca-public-input-v73 / terminal p52 /
frontier-reflection-v45`. The 12 Telecom cases were run once with four-way
concurrency while one Market unseen safety case ran alongside them. Labels were
available only to the isolated evaluator.

- v0.2.3 baseline: `5/12` official strict, `6.17/12` official partial.
- v0.2.4: `5/12` official strict, `6.67/12` official partial.
- Strict-correct rows were 11, 32, 33, 34, and 35. Row 15 scored `0.67`; rows 31
  and 36 each scored `0.5`.
- All 12 Telecom runs reached `completed_partial`; none ended in runtime failure,
  context limit, or budget exhaustion.
- The separate Market unseen run produced no Finding or Recommendation, preserved 11
  unresolved material anomalies, and ended with an auditable Abstention.

Row IDs above are evaluation reporting only. They do not appear in Core or Adapter
policy.

## Known limits

- Public Telecom network telemetry still does not consistently distinguish delay from
  loss or provide exact onset time. A Recommendation may therefore receive partial
  rather than strict credit.
- Multiple source-backed onset groups can remain observationally equivalent. RootWalk
  Abstains unless one group is uniquely selectable under the occurrence contract.
- Provider latency remains the main wall-clock cost. Logical reasoning depth is not
  capped early; provider timeout, wall-clock, Tool, Artifact, Context, and sandbox
  limits remain physical safety boundaries.
