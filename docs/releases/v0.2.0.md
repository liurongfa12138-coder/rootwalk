# RootWalk v0.2.0

RootWalk v0.2.0 stabilizes the evidence-driven RCA harness introduced on the
`feature/rootwalk-frontier-reflection` branch. OpenRCA remains an Adapter and an
evaluation suite; benchmark labels and row-specific rules are not part of the
Harness Core.

## Stable contracts

- The full material-anomaly registry is persisted. Context exposes an active page,
  while resolved and inactive events remain available for audit and Exit coverage.
- Reflection owns explicit Evidence polarity (`supports`, `weakens`, `refutes`),
  hypothesis changes, and anomaly dispositions. Runtime validates those decisions
  but does not infer polarity from hypothesis status.
- A formal Finding requires every material event to have an Evidence-backed
  disposition, the selected hypothesis to have a root-cause disposition, no open
  questions, and a mechanism-eligible typed profile.
- Abstention remains valid when public telemetry cannot distinguish mechanisms. It
  preserves unresolved events instead of converting incomplete investigation into a
  Finding.
- Navigation-only Adapter candidates are separate from the material-event page.
  Typed challenger Evidence may add a material event only when the Adapter explicitly
  sets `material_event_ready=true`.
- A bounded closeout Reflection can update already-evidenced state and immediately
  finalize without manufacturing a new Observation.

## Tool and context changes

- Added typed metric and service profiles, trace-edge comparison, deterministic log
  pattern aggregation, peer comparison, onset bounds, and mechanism-specific Finding
  gates.
- Added OpenRCA Telecom public-input preparation and frozen suite specifications.
- Frontier Context uses a grouped EvidenceAssessment polarity index, active anomaly
  pagination, projected topology, and separate non-exhaustive challenger seeds.
- Database availability and connection state transitions have distinct mechanism
  signatures, so an explicit `On_Off_State` transition outranks a generic incoming
  trace error.

## Known limits

- Some Telecom cases do not expose enough public evidence to distinguish network
  delay from loss or database close from connection limit. The stable policy is to
  Abstain or return an auditable Recommendation, not to add benchmark-shaped Core
  rules.
- Model latency still dominates wall-clock time. Four-way evaluation concurrency is
  recommended; reasoning depth and total Frontier model rounds are not logical early
  stop conditions, but physical wall-clock and provider timeouts still apply.
- CPU telemetry can lag the benchmark's injected occurrence time by several minutes.
  v0.2.0 reports observable onset bounds and does not backdate an event without
  source evidence.
