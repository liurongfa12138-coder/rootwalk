# RootWalk v0.2.3

RootWalk v0.2.3 makes terminal evidence requirements match the output dimensions a
task actually requests, and adds a source-backed Recommendation path for material
events that prove an incident without yet proving a formal root-cause mechanism.
OpenRCA remains an Adapter and evaluation suite; Harness Core contains no benchmark
row, component, answer, label, or evaluator-tolerance branches.

## Output-aware terminal contracts

- A task that requests only root-cause occurrence time may emit a low-confidence
  occurrence Recommendation without claiming a component or reason.
- The model must explicitly select typed Evidence refs. Runtime requires the Evidence
  to share one subject and one overlapping onset interval inside the incident window.
- All registered material anomaly mechanisms must be profiled before occurrence
  selection. A partial first page cannot close the task.
- Selection is allowed only for one unique material-ready onset group, or one unique
  corroborated onset group when no material-ready group exists. Ambiguous public
  telemetry produces Abstention.
- Occurrence Recommendations do not resolve material anomalies and never become
  formal Findings. The exporter independently reconstructs the Evidence group, onset
  intersection, midpoint, audit event, and policy provenance before emitting time.

The frozen Telecom time-only cases still Abstain because public telemetry exposes
multiple equally source-backed onset groups. This is intentional: the new contract
adds a general capability without converting ambiguity into a benchmark guess.

## Material-event Recommendations

- The Telecom Adapter now assigns `peer_isolated_trace_error_event` when incoming
  trace error count and rate form one peer-isolated material event.
- This signature is eligible for an audited Recommendation even when
  `fault_type_ready=false`. It remains ineligible for a formal Finding, which still
  requires mechanism-ready Evidence and complete anomaly coverage.
- Hypothesis creation, leader selection, current-best support, Runtime recommendation
  generation, and exporter validation all apply the same material-event eligibility
  rule.
- Generic pressure without an explicit mechanism signature remains ineligible. The
  Market unseen safety run therefore still ends in Abstention.

This closes a general gap between `material_event_ready` and `fault_type_ready`: a
source-backed incident event can guide a low-confidence next action without being
misrepresented as completed causal proof.

## Frozen evaluation

The release candidate is `m104 / openrca-public-input-v72 / terminal p43 /
frontier-reflection-v36`. The 12 Telecom cases were run once with four-way
concurrency; Market unseen ran alongside them. Labels were available only to the
isolated evaluator.

- v0.2.2: `4/12` official strict, `5.17/12` official partial.
- v0.2.3: `5/12` official strict, `6.17/12` official partial.
- Strict-correct rows were 11, 32, 33, 34, and 35. Row 15 scored `0.67`; row 31
  scored `0.5`.
- All 12 Telecom runs reached `completed_partial`; none ended in runtime failure,
  context limit, or budget exhaustion.
- Market unseen produced no Finding or Recommendation and preserved all five material
  anomalies as unresolved.

Row IDs above are evaluation reporting only. They do not appear in Core or Adapter
policy.

## Known limits

- Public Telecom network telemetry still does not consistently distinguish delay from
  loss. The Adapter keeps those profiles non-ready instead of encoding benchmark
  answers.
- Multiple source-backed onset groups can remain observationally equivalent. RootWalk
  Abstains unless one group is uniquely selectable under the occurrence contract.
- Provider latency remains the main wall-clock cost. Logical reasoning depth is not
  capped early; provider timeout, wall-clock, Tool, Artifact, Context, and sandbox
  limits remain physical safety boundaries.
