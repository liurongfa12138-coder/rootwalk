# RootWalk v0.2.5

RootWalk v0.2.5 aligns signature-free typed fault Evidence across Adapter, dynamic
frontier, anomaly disposition, Finding validation, and OpenRCA export. OpenRCA remains
an Adapter and evaluation suite; Harness Core contains no benchmark row, component,
answer, label, or evaluator-tolerance branches.

## Audited signature-free fault Evidence

- A typed profile with `fault_type_ready=true` no longer becomes unusable merely
  because its `mechanism_signature` is null.
- Signature-free Evidence is eligible only when the Adapter emits
  `signature_free_finding_ready=true`. For metric profiles this requires at least one
  fault-type anchor to meet the existing 20% p95 material distribution-shift standard;
  service profiles may qualify through multi-replica consensus.
- The Evidence records the exact `material_effect_metric_ids`, so Runtime and reviewers
  can reconstruct why the gate passed. The model cannot set or infer this flag.
- Material-event-only Evidence still requires an explicit mechanism signature, and a
  signature-free profile remains ineligible for a low-confidence Recommendation.

## Anomaly disposition safety

- `concurrent_noncausal` now requires an explicit winning Hypothesis with same-subject
  `supports` from either a non-boundary mechanism signature or the audited
  signature-free Finding gate.
- Generic pressure cannot clear rival anomaly slots through prose. Runtime validates
  the root support and rejects refuted or ungrounded winners.
- A formal Finding still requires every material anomaly to have an Evidence-backed
  disposition and the selected Hypothesis to own a root-cause disposition.

This preserves the state-ownership boundary: the model proposes Hypotheses, Evidence
polarity, dispositions, and the leader; Runtime validates the submitted state but does
not manufacture the conclusion.

## OpenRCA export consistency

- Bank now exports the public fault type bound by typed Evidence instead of exporting
  the model's explanatory Hypothesis statement as `root cause reason`.
- Occurrence export ranks both `fault_type_ready` and signed `material_event_ready`
  profiles by causal mechanism rank. A rank-3 trace-error event therefore outranks a
  rank-1 generic trace edge when both support the same Hypothesis.
- The isolated evaluator reports exporter version `rootwalk-openrca-csv-v5`.

## Frozen evaluation

The Runtime candidate is `m115 / openrca-public-input-v74 / terminal p54 /
frontier-reflection-v47`, with OpenRCA exporter v5. Bank 17 and Telecom 12 were each
run once through one five-way-concurrency queue. Labels were available only to the
isolated evaluator.

- Bank v0.2.4 baseline: `0/17` official strict, `0/17` official partial.
- Bank v0.2.5: `2/17` official strict, `2.0/17` official partial. Strict-correct rows
  were 75 and 128.
- Telecom v0.2.4 baseline: `5/12` official strict, `6.67/12` official partial.
- Telecom v0.2.5: `5/12` official strict, `6.67/12` official partial. Strict-correct
  rows remained 11, 32, 33, 34, and 35; row 15 scored `0.67`, and rows 31 and 36
  scored `0.5`.
- All 29 runs reached `completed_partial`; none ended in runtime failure, context
  limit, or budget exhaustion.
- Market unseen produced no Finding or Recommendation and preserved all 19 material
  anomalies as unresolved.

Row IDs above are evaluation reporting only. They do not appear in Core or Adapter
policy.

During investigation, an operator-side broad source search accidentally displayed
Telecom label text. That output was quarantined and was not used in code, Prompt,
threshold, or case-policy decisions. The 20% gate was derived from the existing public
metric-shape contract, tested against Bank public Evidence and the Market counterexample;
Telecom was used only as a no-regression suite for this release.

## Known limits

- Bank improved from zero to two strict cases, but most cases still lack a complete
  Evidence-backed anomaly explanation before physical closeout.
- Provider latency remains the main wall-clock cost. Logical reasoning depth is not
  capped early; provider timeout, wall-clock, Tool, Artifact, Context, and sandbox
  limits remain physical safety boundaries.
- Signature-free material effect is evidence of a fault-type-level incident, not a
  causal path. Multi-component propagation still requires trace, log, or equivalent
  source-backed evidence.
