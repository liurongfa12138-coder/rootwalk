# RootWalk v0.2.6

RootWalk v0.2.6 makes state-dependent structured-output requirements enforceable at
the model-provider boundary. OpenRCA remains an Adapter and evaluation suite; Harness
Core contains no benchmark row, component, answer, label, or evaluator-tolerance
branches.

## Dynamic response Schema

- Frontier Context now emits an allowlisted response constraint only when every
  unresolved anomaly on the active page has an Evidence-backed disposition path and a
  supported current-best Hypothesis exists.
- In that state, the provider JSON Schema sets
  `Reflection.anomaly_disposition_update.minItems=1`. Exploration, unsupported pages,
  physical closeout, and Market-without-a-leader keep the normal unconstrained Schema.
- The ModelAdapter enforces the same constraint after deserialization because provider
  `strict` JSON Schema does not reliably enforce `minItems`. An empty array is marked
  `invalid_response` and receives at most two bounded JSON repair attempts inside the
  same logical model call.
- Every provider request and repair remains in the RunBundle. Runtime receives only a
  schema-valid Decision; it does not infer a disposition from prose or generate any
  Evidence reference.

This preserves state ownership: the model still chooses anomaly disposition,
Hypothesis ID, Evidence refs, explanation, and next operation. Harness only guarantees
that a required structured state update is not silently replaced by decision-summary
text.

## Evaluation budget

The frozen candidate uses a 1,200-second wall-clock boundary instead of 900 seconds.
Logical reasoning, model-call, Tool, Artifact, Context, validator, provider timeout,
and sandbox limits are unchanged. The extra five minutes reduce variance from slow
provider responses while preserving the same physical closeout reserve.

## Frozen evaluation

The Runtime candidate is `m119 / openrca-public-input-v74 / terminal p56 /
frontier-reflection-v50`, with OpenRCA exporter v5. Bank 17 and Telecom 12 were each
run once through one five-way-concurrency queue. Labels were available only to the
isolated evaluator.

- Bank v0.2.5 baseline: `2/17` official strict, `2.0/17` official partial.
- Bank v0.2.6: `2/17` official strict, `2.5/17` official partial. Strict-correct rows
  remained 75 and 128; row 122 added `0.5` partial credit.
- Telecom v0.2.5 baseline: `5/12` official strict, `6.67/12` official partial.
- Telecom v0.2.6: `5/12` official strict, `6.67/12` official partial. Strict-correct
  rows remained 11, 32, 33, 34, and 35; row 15 scored `0.67`, and rows 31 and 36
  scored `0.5`.
- All 29 runs reached `completed_partial`; none ended in runtime failure, context
  limit, or budget exhaustion.
- Market unseen produced no Finding or Recommendation and preserved all 19 material
  anomalies as unresolved under the same 1,200-second wall-clock boundary.

Row IDs above are evaluation reporting only. They do not appear in Core or Adapter
policy. Telecom remained a no-regression suite and was not used to tune this change.

## Verification

- Default engineering suite: `800 passed, 9 deselected`.
- Official Bank fixture: `9 passed`.
- Frontier-focused regression suite: `39 passed`.
- Ruff check and format, Pyright strict mode, `uv lock --check`, and
  `git diff --check` pass.

## Known limits

- Bank gains only `0.5` partial credit in this release; most zero-score cases still do
  not expose an eligible typed root-cause profile in public telemetry.
- Dynamic local repair improves empty-state reliability but adds provider attempts when
  the model repeatedly violates the response constraint. The frozen 29-case run
  recorded 39 invalid provider attempts across 246 provider attempts.
- Provider latency remains the main wall-clock cost. The longer physical budget is not
  a substitute for stronger Evidence, and Market remains an explicit safety gate.
